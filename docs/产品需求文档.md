# 小说工作台 PRD

## 1. 产品定位

小说工作台是一个面向长篇小说的本地创作辅助工具。它把一部小说的资料、章节与生成记录保存在独立本地项目中，用“步骤化流程 + LLM 生成 + 固定格式资产”的方式，帮助用户从初始化资料开始，逐步生成世界观、角色卡、剧情、章节正文与校验报告。

核心价值：

- 每步只做一件事，产物可追溯、可撤回、可重试。
- 用户原始信息持续累积，后续每一步都携带完整上下文。
- 所有正式资产以普通文件保存在项目目录中，用户可随时查看、编辑和版本管理。
- 支持原创与同人两种项目；同人项目增加原著提取流程。

## 2. 目标用户与使用场景

- 目标用户：长篇网文/小说作者、设定控、AI 辅助写作用户。
- 场景：
  - 从零开始新建一部小说，逐步建立世界观、角色、关系、剧情。
  - 同人创作：先上传原著，提取文风/词库/高频词，再进入正式创作。
  - 逐章生成：锚点 → 配置 → 台词 → 提示词快照 → 正文 → 校验。
  - 对已生成的全局资产（世界观、角色卡、关系卡、信息账本等）进行局部更新。

## 3. 核心原则

1. **发送与下一步统一**：输入框的“发送”与流程栏的“下一步”调用同一个当前步骤；发送会追加用户补充，下一步不追加文字但携带已累积的完整上下文。
2. **不猜关键事实**：初始化资料、章节资料先判别，缺少角色或剧情时只要求补充，不直接生成正式资产。
3. **用户信息连续累积**：初始化和每个章节分别维护一份已认可的原始信息文件；后续发送的补充按时间追加，所有下游 LLM 步骤都读取完整累积信息。
4. **上下文可追溯**：每次生成记录执行日志（LLM 调用、token、耗时、错误）；失败不覆盖正式产物。
5. **全局资产可更新**：顶部“可更新”区提供小说简介、世界观、语言风格、角色名单、角色卡、关系卡、信息账本、剧情书的生成/更新入口。
6. **格式门禁分层**：正文生成步骤不做严格格式拦截，格式与语义问题留给“校验与验收”步骤；其他固定格式资产在写入前仍做结构校验。

## 4. 功能范围

### 4.1 已实现

- 本地项目创建/删除/重命名/切换。
- 原创与同人项目。
- 同人原著上传与五步提取：原文统计、高频词、原文风格、正向词库、专属词库。
- 初始化：小说资料判别、简介、世界观 JSON、语言风格、角色名单、批量角色卡、批量关系卡、剧情书、剧情卷、信息账本。
- 章节：章节信息判别、强制设定锚点、配置、台词、最终提示词快照、正文、校验与验收。
- 正文草稿另存、章节评分。
- 顶部“可更新”全局资产一键生成/更新。
- 步骤完成卡：打开、撤回、重试、下一步；正文支持草稿和评分。
- 失败卡片：显示错误详情、模型、输入/输出 token、耗时；校验类失败显示为“校验未通过”。
- 用量统计：顶部显示项目累计总输入/总输出；用量写入 `运行记录/workflow-state.json`，并从执行日志回填历史用量。
- 模型设置：提供方、模型、API Key、思考强度、分步骤模型覆盖。

### 4.2 未纳入当前版本

- 正文验收后的“资产增量更新任务”尚未实现；当前验收通过仅更新流程状态和提示文案。
- 原文向量索引。
- SQLite 状态库、版本快照、Git 自动提交尚未接入当前工作台。
- 手动模式的完整结构化表单门禁尚未完全覆盖所有步骤。

## 5. 项目与文件存储

### 5.1 项目目录

每个小说项目位于 `小说项目/<类型>-<小说名>/`，类型只允许 `原创` 或 `同人`。

```text
<类型>-<小说名>/
├─ 原著/                     # 同人上传的参考文本
├─ 提取/                     # 同人提取产物
├─ 知识库/
│  ├─ 小说简介.md / .json
│  ├─ 世界观.md / .json
│  ├─ 语言风格.md / .json
│  ├─ 角色名单.md / .json
│  ├─ 角色卡/角色卡-<角色名>.md / .json
│  ├─ 关系卡/关系卡-<A>-<B>.md / .json
│  └─ 信息账本.md / .json
├─ 词汇库/
│  ├─ 人物词库.md
│  ├─ 对话词库.md
│  ├─ 通用词库.md
│  └─ 禁用词库.md
├─ 剧情/
│  ├─ 剧情书.md / .json
│  └─ 剧情卷/<卷名>.md / .json
├─ 提示词/
│  └─ <章节名>/
│     ├─ 强制设定锚点.md / .json
│     ├─ 配置.md
│     ├─ 台词.md / .json
│     ├─ 最终提示词快照.md
│     └─ 校验报告.md / .json
├─ 正文/<章节名>.txt
├─ 草稿/<章节名>-改写预览.txt
├─ 评分/<章节名>评分.md
└─ 运行记录/
   ├─ workflow-state.json
   ├─ 对话记录.md
   ├─ 初始化资料.md
   ├─ 章节输入/<章节名>.md
   └─ 执行记录/*.jsonl
```

### 5.2 JSON + Markdown 双文件

固定格式资产统一生成两个文件：

- `xxx.json`：结构化源文件，程序读写与后续上下文使用，网页隐藏。
- `xxx.md`：自动渲染的可读版，网页右侧展示。

### 5.3 运行记录

- `workflow-state.json`：当前项目初始化进度、章节进度、用户输入、用量统计。
- `执行记录/*.jsonl`：每次 LLM 调用的模型、token、耗时、成功/失败信息。
- `对话记录.md`：当前工作台对话快照，用于刷新后恢复聊天区。

## 6. 完整流程

```text
新建项目
→ 小说资料输入与判别
→ 简介
→ 世界观
→ 语言风格
→ 角色名单
→ 批量角色卡
→ 批量关系卡
→ 剧情书
→ 剧情卷
→ 信息账本
→ 完成初始化

新建章节
→ 本章信息判别
→ 强制设定锚点
→ 配置
→ 台词
→ 最终提示词快照
→ 正文
→ 校验与验收
→ （规划中：资产增量更新）
→ 下一章
```

同人项目在初始化前插入：

```text
上传原著
→ 原文统计 → 高频词 → 原文风格 → 正向词库 → 专属词库
→ 小说资料输入与判别
```

## 7. 初始化流程

### 7.1 小说资料输入与判别

- 用户提交角色表、背景、事件线、剧情梗概等任意长度资料。
- 判别器只判断：是否有角色、是否有剧情。
- 缺少时提示“补充主角信息 / 补充剧情梗概”，不生成正式文件。
- 通过后保存到 `运行记录/初始化资料.md`，再生成 `知识库/小说简介.md` 与 `知识库/小说简介.json`。

### 7.2 初始化步骤

| 步骤 | 输入 | 读取 | 产出 |
| --- | --- | --- | --- |
| 小说简介 | 判别结果、完整初始化资料 | 初始化资料 | `知识库/小说简介.md/.json` |
| 世界观 | 用户补充 | 简介、初始化资料、剧情书、信息账本 | `知识库/世界观.md/.json` |
| 语言风格 | 用户补充 | 简介、初始化资料、世界观、同人原文风格 | `知识库/语言风格.md/.json` |
| 角色名单 | 用户补充 | 简介、初始化资料 | `知识库/角色名单.md/.json` |
| 批量角色卡 | 用户补充 | 角色名单、世界观、信息账本、人物词库 | `知识库/角色卡/角色卡-*.md/.json` |
| 批量关系卡 | 用户补充 | 角色名单关系，或已有关系卡 | `知识库/关系卡/关系卡-*.md/.json` |
| 剧情书 | 用户补充 | 简介、初始化资料、知识库 | `剧情/剧情书.md/.json` |
| 剧情卷 | 用户补充 | 剧情书、知识库 | `剧情/剧情卷/<卷名>.md/.json` |
| 信息账本 | 用户补充 | 剧情书、剧情卷 | `知识库/信息账本.md/.json` |

初始化期间，用户可继续在输入框补充资料；补充内容会追加到 `运行记录/初始化资料.md`。

## 8. 章节流程

### 8.1 新建章节与章节信息门禁

- 新建章节后从“锚点”阶段开始。
- 用户提交本章原始信息。
- 判别器要求：至少提到一名已知角色，且有具体剧情梗概或因果推进。
- 通过后保存到 `运行记录/章节输入/<章节名>.md`，再生成锚点。

### 8.2 章节步骤

| 步骤 | 读取 | 产出 |
| --- | --- | --- |
| 强制设定锚点 | 本章完整用户信息、简介、世界观、角色卡、关系卡、剧情卷、信息账本 | `提示词/<章节>/强制设定锚点.md/.json` |
| 配置 | 锚点、世界观、语言风格 | `提示词/<章节>/配置.md` |
| 台词 | 锚点、角色卡、关系卡、语言风格、对话词库 | `提示词/<章节>/台词.md/.json` |
| 最终提示词快照 | 世界观、语言风格、相关角色卡/关系卡、锚点、配置、台词、词库、上一章结尾 | `提示词/<章节>/最终提示词快照.md` |
| 正文 | 最终提示词快照 | `正文/<章节>.txt` |
| 校验与验收 | 正文、锚点、世界观、角色卡、关系卡、语言风格 | `提示词/<章节>/校验报告.md/.json` |

### 8.3 正文与校验

- 正文生成只要求非空即可落盘，不再做 `---`、引号、方括号等格式门禁。
- 格式与语义问题由“校验与验收”步骤统一检查。
- 正文完成卡支持“草稿”和“评分”。

## 9. 顶部“可更新”全局资产

页面顶部“可更新”区域包含以下模块：

| 模块 | 调用脚本 | 产出 |
| --- | --- | --- |
| 小说简介 | `compile_intro` | `知识库/小说简介.md/.json` |
| 世界观 | `generate_worldview_json` | `知识库/世界观.md/.json` |
| 语言风格 | `compile_style` | `知识库/语言风格.md/.json` |
| 角色名单 | `compile_character_roster` | `知识库/角色名单.md/.json` |
| 角色卡 | `generate_characters_batch` | `知识库/角色卡/角色卡-*.md/.json` |
| 关系卡 | `generate_relations_batch` | `知识库/关系卡/关系卡-*.md/.json` |
| 信息账本 | `compile_ledger` | `知识库/信息账本.md/.json` |
| 剧情书 | `compile_plot` | `剧情/剧情书.md/.json` |

交互：

- 点击模块后，底部输入框上方显示“本次生成：<模块> ×”。
- 用户填写要求并发送后，调用对应脚本生成/更新文件。
- 角色卡/关系卡支持批量更新；关系卡在角色名单缺少 relations 时会读取已有关系卡 JSON 作为更新来源。

## 10. 交互模式

| 模式 | 说明 |
| --- | --- |
| 手动 | 用户按结构化字段填写后执行（当前仅部分文件支持右侧“结构化编辑”，尚未完整覆盖所有步骤）。 |
| 标准 | 直接发送自然语言，产物生成并校验后由用户选择撤回/重试/下一步。 |
| 自动 | 产物生成成功后自动进入下一步；遇到已有文件需要确认或缺少用户输入时暂停。 |

当前版本：

- 标准模式：完整可用。
- 自动模式：已实现基础连续执行（初始化与章节流程可自动推进）。
- 手动模式：仍是界面选项，尚未作为完整模式接入所有步骤。

## 11. 失败处理与用量

- 执行失败时保留错误详情，不覆盖正式产物。
- 失败卡片显示模型、输入 token、输出 token、耗时（如果本次已有 LLM 调用）。
- 校验类错误（格式未通过、枚举只能选择、语义校验等）显示为“校验未通过”，而不是“流程未执行”。
- 顶部“总输入 / 总输出”为项目累计值；失败产生的 token 消耗也会计入。
- 用量持久化在 `运行记录/workflow-state.json`；历史用量可从 `运行记录/执行记录/*.jsonl` 自动回填。

## 12. 验收与测试

- `工作流脚本/验证完整流程.py`：无模型完整流程集成验证。
- `工作流脚本/验证工作台验收.py`：端到端验收，覆盖项目创建/上传/切换/删除、初始化、章节流程、前端契约；默认不调用真实模型。
- `工作流脚本/验证工作台验收.py --live-model`：真实调用已配置 API，完整执行初始化与章节生成。

## 13. 非目标

- 不提供云端多用户、在线协作。
- 不提供正文自动发布/排版。
- 不保存用户输入明文之外的额外个人数据。
- 不自动提交 Git 历史（当前版本由外部 Git 管理）。
