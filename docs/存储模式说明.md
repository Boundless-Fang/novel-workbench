# 小说项目存储模式

## 结论

每部小说使用独立 Git 仓库。

小说资产以普通文件保存在项目目录中，Git 记录每次保存后的版本历史；两者不冲突：Git 管理的对象就是这些文件。

```text
小说项目目录
├─ 原著/
├─ 提取/
├─ 知识库/
├─ 剧情/
├─ 提示词/
├─ 正文/
├─ 草稿/
├─ 评分/
└─ .git/
```

## 纳入 Git 的资产

- 正文
- 世界观、语言风格、角色卡、关系卡、信息账本
- 剧情书、剧情卷、章节大纲
- 强制设定锚点、配置、台词、最终提示词快照、校验报告
- 用户确认保留的草稿与评分报告

## 统一模式：JSON 结构化源 + Markdown 可读版

每个固定格式步骤同时生成两个文件：

- `xxx.json`：结构化源文件，程序读写与校验使用，网页隐藏；
- `xxx.md`：自动渲染的可读版，网页右侧只显示这个。

| 资产 | JSON 文件 | 对应显示 Markdown |
|---|---|---|
| 简介 | `知识库/小说简介.json` | `知识库/小说简介.md` |
| 世界观 | `知识库/世界观.json` | `知识库/世界观.md`（已完成） |
| 语言风格 | `知识库/语言风格.json` | `知识库/语言风格.md` |
| 角色卡 | `知识库/角色卡/角色卡-xxx.json` | `知识库/角色卡/角色卡-xxx.md` |
| 关系卡 | `知识库/关系卡/关系卡-A-B.json` | `知识库/关系卡/关系卡-A-B.md` |
| 剧情书 | `剧情/剧情书.json` | `剧情/剧情书.md` |
| 剧情卷 | `剧情/剧情卷/第N卷.json` | `剧情/剧情卷/第N卷.md` |
| 信息账本 | `知识库/信息账本.json` | `知识库/信息账本.md` |
| 锚点 | `提示词/第X章/强制设定锚点.json` | `提示词/第X章/强制设定锚点.md` |
| 台词 | `提示词/第X章/台词.json` | `提示词/第X章/台词.md` |
| 校验报告 | `提示词/第X章/校验报告.json` | `提示词/第X章/校验报告.md` |

台词格式固定为：

```text
<角色名> + “<台词>”
<角色名> + “ [心声]”
```

## 提交规则

以下动作完成后自动提交当前项目仓库：

- 用户主动保存文件。
- 脚本成功生成或重写产物。
- 用户通过章节验收。
- 用户确认覆盖已有资产。
- 生成正文前冻结最终提示词快照。

提交信息使用统一格式：

```text
[第3章] 生成章节大纲
[第3章] 生成正文
[第3章] 校验通过
[角色卡] 更新沈栖迟
[快照] 冻结第3章生成上下文
```

自动保存应进行短暂防抖（建议 10 至 30 秒），合并连续编辑，避免产生大量没有意义的提交。

## 回退原则

- 可按文件查看历史版本和差异。
- 优先只回退目标文件，不回退整部小说。
- 生成、改写、验收等关键动作前可创建 Git checkpoint。
- 回退后应重新校验依赖该文件的后续产物，并提示用户是否重建大纲、快照或正文。

## SQLite 的可选职责

SQLite 不保存小说正文的主版本，只保存系统运行状态，例如：

- 当前项目、卷、章节与流程步骤。
- 脚本输入 JSON、任务日志、校验结果。
- 每个产物对应的文件路径、内容 hash、Git commit hash。
- 待用户确认的澄清请求和状态提案。

因此：文件系统保存可读资产，Git 保存资产历史，SQLite 保存工作流状态与索引。
