# Skill: novel-extract-source（同人原著信息提取，无 RAG）

## 用途
仅用于**同人项目**：从 `<项目>/原著/` 中的原作原文提取可复用的"原文信息"：
1. **f1a** 本地文本统计（段落/句长、标点、对话结构、词汇丰富度、词性分布）
2. **f1b** LLM 风格特征（叙事节奏、语体、人称、句段、心理、对话、标点、手法偏好等）
3. **f2a** 本地高频词
4. **f2b** LLM 正向词库（按容貌/气质/身材/服饰/对话/交互/环境等维度清洗）

**不构建向量索引（不建 RAG）**。f2b 需要原文片段时，用 `novel-search` skill 按关键词检索原文。

原创项目没有 `原著/` 目录，不使用本 skill；如需风格参考，直接把用户给的参考文风描述写进世界观卡或语言风格素材。

## 触发条件
- 同人项目开始前，用户要求"提取原作文风/词库/写作特征"
- 希望"按原作的风格/用词来写同人"
- 需要在写作流程开始前，先准备好原著风格与词库资产

## 前置依赖
- `DEEPSEEK_API_KEY`（f1b/f2b 需要；只做本地统计可跳过）
- 原作原文已放入 `<项目>/原著/`

## 流程
- **f1a 本地统计**：用持久 shell 统计段落数、句长分布、对话行占比等物理指标，写入 `原文统计指标.txt`。
- **f1b 风格特征**：按检查模型约定（见 novel-conventions skill《通用约定·模型》）让 LLM 归纳叙事节奏、语体、人称、句段、心理、对话、标点、手法偏好，写入 `原文风格特征.md`。
- **f2a 高频词**：用 shell 分词/计数得到高频词表，写入 `原文高频词.txt`。
- **f2b 正向词库**：结合 f2a 与 `novel-search` 召回的片段，按容貌/气质/身材/服饰/对话/交互/环境维度清洗出正向用词，写入 `原文正向词库.md`；所有词必须能在原文中找到出处，不得由 LLM 自造。

## 输出（固定路径）
```
<项目>/知识库/原文信息/
├─ 原文统计指标.txt      # f1a
├─ 原文风格特征.md       # f1b
├─ 原文高频词.txt        # f2a
└─ 原文正向词库.md       # f2b
```

## 交给其他 skill
- `原文风格特征.md` → 可作为 stage4-prose（正文）的文风参考，或合并进当前模式素材目录下的语言风格文件
- `原文正向词库.md` → 可作为 stage3（对话）和 stage4（正文）的用词参考，或并入当前模式素材目录下的通用词库
- `原文高频词.txt` → 用于观察作者高频用词，辅助生成时避免/沿用
- `原文统计指标.txt` → 用于把握句长、段落、对话结构等物理风格

## 检查清单
- [ ] 项目为同人（存在 `<项目>/原著/`）；原创项目未误用本 skill
- [ ] 四个输出文件均已生成
- [ ] `原文风格特征.md` 包含结构化摘要 + 行文风格 + 格式要求 + 手法偏好 + 具体内容
- [ ] `原文正向词库.md` 的词均来自原文，没有 LLM 自造词
- [ ] 没有生成 `global_rag_db` / `vector.index` / `chunks.json`（本 skill 不建 RAG）
- [ ] 若后续需要从原文按需取片段，调用 `novel-search`，不要依赖 RAG 索引

## 失败处理
- 找不到参考原文 → 核对 `<项目>/原著/` 下是否有原作文本。
- LLM 调用失败 → 检查 `DEEPSEEK_API_KEY` / `.env`，先落 f1a/f2a 本地产物再重试。
