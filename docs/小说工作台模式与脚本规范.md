# 小说工作台模式与脚本规范

## 核心原则

每个流程步骤对应一个脚本。脚本负责接收用户输入、读取该步骤所需的项目文件、调用指定的 LLM/API，并将结果按固定格式写入规定文件。

```text
用户输入
→ 当前步骤脚本
→ 指定 LLM/API
→ 指定格式产物
→ 自动校验
→ 按模式决定确认或下一步
```

脚本不是由工作台对话 AI 代写最终文件的工具；LLM 的生成结果由脚本保存为标准项目资产。

## 脚本输入

每个脚本都支持两种输入方式，最终都归一为同一份步骤数据：

1. **自然语言输入**：用户直接描述需求。脚本把自然语言和本步骤规则发送给指定 LLM，由 LLM 提取或补全所需字段，再生成指定格式文件。
2. **结构化输入**：用户通过右侧文件查看中的结构化编辑器，按字段填写 JSON/表单数据。结构化表单同样只是输入：字段未填完整或需要润色时，脚本将其发送给指定 LLM 补全后再生成文件；只有用户明确填写完整且无需补全时，确定性模板步骤才可直接使用字段。

脚本自行读取本步骤所依赖的已确认项目文件，例如正文脚本读取大纲、台词、世界观、角色卡和上一章正文；用户不需要重复输入已有资产。

## 三种模式

| 模式 | 用户输入 | 每一步完成后 |
| --- | --- | --- |
| 手动模式 | 用户按指定结构填写字段 | 用户确认后才执行或进入下一步 |
| 标准模式 | 用户直接发送自然语言 | 产物生成并校验后，由用户选择撤回、重试或下一步 |
| 自动模式 | 用户直接发送自然语言 | 产物生成并校验后自动进入下一步，无需逐步确认 |

三种模式使用同一批脚本、同一套目录和相同的校验规则；区别仅在输入方式与是否需要用户确认。

## 步骤脚本应声明的内容

- 输入：接受自然语言、结构化字段，或两者之一。
- 依赖：执行前必须存在的项目文件。
- 模型：本步骤使用的 API、模型与参数；不同脚本可以不同。
- 输出：生成的文件路径、名称与格式。
- 校验：文件存在、结构完整、格式/内容规则。
- 失败处理：重试当前步骤、撤回本次产物或返回上一步。

## 确认、撤回与重试

- 手动模式：用户确认输入后执行；完成后用户再决定下一步。
- 标准模式：脚本完成后显示产物和校验结果，用户可撤回、重试或下一步。
- 自动模式：校验通过即自动进入下一步；失败时按当前步骤的重试规则处理。
- 撤回应回退本次步骤产生或覆盖的文件版本；重试只重跑当前步骤，不重跑全流程。

## 反问功能

当自然语言缺少关键字段、存在歧义或与已有设定冲突时，脚本可记录“需要补充的信息”和建议选项。

反问交互暂不在当前版本上线：当前版本只记录该信息，并将步骤标记为需要补充或执行失败，不自动向用户发起追问。

## 范围

本规范描述小说项目的步骤驱动生成方式。具体目录、文件命名和完整步骤顺序以 `完整流程与选择规范.md` 为准。
